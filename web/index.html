Project overview

U-RESCUE is a terrain-screening prototype for exploring nearby high-elevation samples and available walking routes in the configured Hyderabad and Sangareddy, Telangana study area.

Configured extent: 77.5–78.6° E, 17.1–17.8° N. Terrain samples are approximately 371 m apart.

Research prototype Results are not confirmed shelters or safe routes.

Formulas and model

Terrain screening score:

T = 0.55 × (1 − elevation rank) + 0.45 × clip(1 − slope / 25°, 0, 1)

Elevation rank is relative within the sampled grid. Slope is calculated from elevation change and approximate horizontal spacing. Larger T indicates relatively lower, gentler terrain under this heuristic; it is not a flood probability.

Nearby-point search: great-circle distance from the selected origin is calculated with a haversine formula. Valid samples inside the chosen radius are sorted by elevation; adjacent candidates within 500 m are suppressed so the results are spatially distinct.

Route cost model in the codebase:

C(edge) = L × [w_d + w_r × (mean terrain score + w_u × unknown flag)]

Configured values are distance weight 1.0, risk weight 3.0, unknown-data penalty 0.35. This cost model is not used by the current map search to choose its displayed walking routes: those are requested from Valhalla. Observed-flood and closure inputs are currently unset.

What the app does

  • Choose a search point by map click or browser location permission.
  • Select a search radius from 1 to 20 km.
  • Return up to two highest distinct valid elevation samples in that radius.
  • Request and display available walking paths to those points.
  • Show elevation, straight-line distance, and route length when available.

Technology stack

  • Frontend: HTML, CSS, JavaScript.
  • Map: MapLibre GL JS with OpenFreeMap Liberty vector style.
  • Backend: Python and FastAPI.
  • Terrain processing: NumPy and local Python processing.
  • Walking routes: public FOSSGIS Valhalla demo using OpenStreetMap data.
  • Hosting: Vercel.
  • Source repository: GitHub · U-RESCUE.

Datasets and services

  • Elevation: two supplied local HGT tiles, n17e077 and n17e078. Their original provider and acquisition date are not recorded in the workspace. They are not fetched from a live elevation API.
  • Road/path network: OpenStreetMap through the Valhalla route service at request time; route availability depends on the public service and mapped pedestrian paths.
  • Basemap: OpenFreeMap vector tiles, displayed through MapLibre.
  • Flood, rainfall, drainage, closure, shelter, and infrastructure hazard observations: not configured in the current app.

API endpoints

  • GET /api/status — readiness and configured hazard-data status.
  • GET /api/elevated-areas?lon=&lat=&radius_km= — up to two high sampled terrain points and available walking routes.
  • POST /api/routes — request a walking route for supplied start and destination coordinates.
  • GET /api/layers — terrain grid features.
  • GET /api/safe-zones — low-confidence terrain screening candidates; not verified safe zones.
  • GET /api/hazards — configured hazard polygons, if any.

Limitations and responsible use

  • Coarse terrain samples do not resolve street-level elevation, drainage, barriers, or water depth.
  • No observed flood events, active rainfall, closures, or verified shelters are currently configured.
  • Walking paths reflect mapped network data and do not establish current access or passability.
  • No user-trial count, response-time benchmark, or flood-event validation is recorded in the project materials.
  • Use local emergency-service instructions and current authority information during an emergency.
